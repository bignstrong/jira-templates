# 📋 Jira Issue Templates

Готовые шаблоны описаний задач для Jira на **wiki-разметке** (Text Formatting Notation).
Скопировал шаблон → вставил в поле *Description* → заполнил плейсхолдеры. Единый вид у всех задач, ничего важного не забывается.

> Разметка работает в полях с режимом рендеринга **Wiki Style Renderer**. В новом облачном редакторе вставляй текст в режиме `{}` / Markdown-вставки.

---

## 🧩 Типы шаблонов

| Тип | Файл | Когда брать |
|-----|------|-------------|
| 🚀 **Epic** | [`epic-template.txt`](epic-template.txt) | Крупная фича из нескольких стори/задач (часто сквозная по командам) |
| ⭐ **Story** | [`story-template.txt`](story-template.txt) | Пользовательская ценность: «*как роль, хочу …, чтобы …*» |
| 🛠️ **Task** | [`task-template.txt`](task-template.txt) | Техническая работа без прямой user-story |
| 🐞 **Bug** | [`bug-template.txt`](bug-template.txt) | Что-то сломано: шаги, ожидаем/получаем, root cause |
| 🔎 **Code Review** | [`code-review-template.md`](code-review-template.md) | Ревью MR/PR: чек-лист, замечания с severity, вердикт. **Markdown** — для GitLab/GitHub или комментария в Jira |

### 📂 Структура

```
jira-issue-templates/
├── epic-template.txt        # 🚀 шаблон эпика
├── story-template.txt       # ⭐ шаблон стори
├── task-template.txt        # 🛠️ шаблон задачи
├── bug-template.txt         # 🐞 шаблон бага
├── code-review-template.md  # 🔎 шаблон код-ревью (markdown)
└── README.md
```

> 🇬🇧 Английская версия шаблонов — файлы с приставкой `-en` (`epic-template-en.txt`, …) и [`README-en.md`](README-en.md).

## 🎨 Шпаргалка по разметке

Цвета панелей соответствуют стандартной палитре Jira:

| Панель | `bgColor` | Где используем |
|--------|-----------|----------------|
| 🔵 Инфо / Суть истории | `#DCEAFF` | вводный блок стори |
| 🟣 Суть эпика / задачи | `#EAE6FF` / `#E8E7FF` | вводный блок эпика / задачи |
| 🟢 Критерии приёмки / DoD | `#E3FDEE` | acceptance criteria |
| 🟠 Breaking change | `#FFF0E6` | предупреждение о ломающем изменении |
| 🔴 Суть бага | `#FEEBE7` | вводный блок бага |

Основные конструкции:

```jira
{panel:title=Заголовок|bgColor=#E3FDEE} текст панели {panel}

h3. Заголовок раздела          # h3. / h4. — заголовки
*жирный*  _курсив_             # акценты
{{моноширинный}}               # код / имена полей и веток инлайн
* [ ] чек-лист                 # пункт критериев приёмки
# нумерованный шаг             # тест-кейсы
[Текст|https://ссылка]         # ссылка

{code:json}
{ "пример": "блок кода" }
{code}
```

## ✅ Как пользоваться

1. Открой нужный `*-template.txt` и скопируй содержимое.
2. Вставь в поле **Description** при создании задачи в Jira.
3. Замени плейсхолдеры (`_курсивные подсказки_` и `…`) на реальные данные.
4. Удали неактуальные блоки (напр. панель *Breaking change*, если её нет).
5. Сверься с разделом *Критерии приёмки* до старта разработки.

> 💡 Совет: чек-боксы `* [ ]` в панели критериев — это видимый и кликабельный в Jira трекинг готовности.
