{panel:title=🚀 Epic summary|bgColor=#EAE6FF}
*What large chunk of work, and why.* An epic groups several stories/tasks toward a shared goal.
_E.g.: "Pin chats in folders" — a cross-cutting feature: backend + Android + iOS + Web._
{panel}

h3. 🎯 Goal & business value
What big pain or opportunity we close, and how we'll know the epic succeeded (metric / outcome). _Don't forget the Priority field._

h3. 🧩 Epic scope (child stories)
Child stories/tasks — link them via *Epic Link*.
* (Story) … — _link_
* (Story) … — _link_
* (Task) … — _link_

h3. 🚫 Out of scope
What is deliberately NOT part of the epic, so it doesn't sprawl.
* …

h3. ⏱️ Estimate & milestones
*Rough timeline / sprints:* _e.g. 2 sprints_. Key milestones and sequence.

h3. 📋 Description & context
Architecture, dependencies, API contracts, breaking changes — the big picture for all teams.

h3. 🔌 For clients (iOS / Android / Web)
One place every client team checks for this epic. Child tasks link here instead of retelling it.
* *Contract:* link to the contract page or the feature passport in Confluence
* *Endpoints by service:* ours — link to the operation in Swagger; standard Matrix — link to https://spec.matrix.org/latest/ or the MSC
* *What we take from Matrix as is:* spec sections / MSCs and the server flags we enable for it
* *Available on:* dev since DD.MM / prod since DD.MM

{panel:title=⚠️ Breaking change|bgColor=#FFF0E6}
If the epic breaks an existing contract — describe exactly what, and who we coordinate the release with. Delete this panel if not applicable.
{panel}
